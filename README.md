## 1. О проекте

**«Фонд Района»** решает ключевую проблему любого дома или сообщества — **доверие к общему бюджету**.  
Приложение исключает непрозрачные «переводы на карту председателя в WhatsApp» и ведение учёта на клочках бумаги. Каждый житель видит, сколько денег собрано, на что они потрачены, какие чеки прикреплены к расходам и каков текущий баланс общего счёта.

### Ключевые возможности

1. **Главная (Центр управления)**:
   - Живой баланс фонда и динамика поступлений / расходов за текущий месяц.
   - Персональная карточка статуса жителя: автоматический расчёт задолженности (`DEBT`), переплаты (`ADVANCE`) или статуса «В норме» (`OK`).
   - Быстрое погашение долга в один клик с предзаполненной суммой.
   - Быстрый доступ к банковским реквизитам и счетам фонда для перевода по СБП.
   - Активные целевые сборы с прогресс-баром и процентом сбора.
   - Лента последних операций (доходы / расходы).

2. **Внесение взносов и подтверждение**:
   - Выбор типа взноса: обязательный ежемесячный сбор либо целевой фонд (шлагбаум, озеленение, LED-освещение и т.д.).
   - Автогенерация или прикрепление фото банковского чека / квитанции.
   - Мгновенное попадание в очередь модерации со статусом `PENDING`.

3. **Верификация чеков (Модерация)**:
   - Личный кабинет совета дома и председателя с фильтром непроверенных чеков.
   - Полноэкранный просмотр чека с увеличением (Zoom).
   - Одобрение взноса (`APPROVED`) с автоматическим пересчётом баланса дома и сальдо жильца.
   - Отклонение (`REJECTED`) с обязательным указанием причины, видимой собственнику.

4. **Учёт расходов фонда**:
   - Фиксация трат по категориям (Ремонт, Электрика, Аварийные работы, Хознужды, Озеленение, Видеонаблюдение).
   - Привязка расхода к общему фонду или конкретному целевому сбору.
   - Обязательное прикрепление фото товарных чеков, накладных и актов выполненных работ.

5. **Целевые сборы (Краудфандинг дома)**:
   - Создание целевых сборов с указанием необходимой суммы, описания и категории.
   - Просмотр детальной карточки сбора: собранная сумма, процент выполнения, остаток, список внесших взнос соседей.
   - Возможность поделиться ссылкой на сбор в домовых чатах.
   - Завершение и возобновление сборов.

6. **Доска объявлений и голосования**:
   - Публикация важных новостей дома с возможностью закрепления (Pin).
   - Интерактивные лайки и древовидные комментарии жителей.

7. **Реестр жильцов и контроль долгов**:
   - База собственников помещений (квартира, ФИО, телефон, статус).
   - Регистрация новых жителей через удобную форму.
   - Список должников с точным расчётом неоплаченных месяцев.

8. **Прозрачная финансовая отчётность**:
   - Помесячная сводная ведомость за текущий год.
   - Экспорт реестра взносов в **CSV** (с поддержкой Excel и кодировкой UTF-8 BOM).
   - Экспорт реестра расходов в **CSV**.
   - Экспорт реестра должников в **CSV**.

## 2. Стек технологий

### Frontend
- **Фреймворк**: Vue 3 (Composition API, `<script setup>`, TypeScript).
- **Стейт-менеджмент**: Pinia с персистентностью в `localStorage` (версионированные ключи) и реактивными вычисляемыми геттерами.
- **Сборщик**: Vite 6 (горячая перезагрузка, быстрый билд).
- **Стилизация**: Tailwind CSS v4 + Scss (нативная мобильная вёрстка без тяжелых UI-фреймворков, плавная анимация модальных окон и шторок).
- **Иконки**: `@ant-design/icons-vue`.
- **Архитектура**: **Feature-Sliced Design (FSD v2)**.

### Backend (`/backend`)
- **Язык**: Python 3.10+
- **Фреймворк**: FastAPI (асинхронный REST API, Swagger/OpenAPI автогенерация).
- **База данных**: PostgreSQL 16
- **ORM**: SQLAlchemy 2.0 (декларативные модели, отношения).
- **Миграции**: Alembic.
- **Схемы и валидация**: Pydantic v2 + Pydantic Settings.
- **Безопасность**: JWT-аутентификация, пароли Passlib/Bcrypt, ролевой RBAC.

### Контейнеризация
- **Docker Compose**: Полный стек из 3 сервисов (Postgres 16, FastAPI Backend, Vue 3 Frontend Nginx).

## 4. Финансовая модель и бизнес-логика

### 4.1. Расчёт баланса фонда
$$\text{Общий баланс} = \sum \text{Взносы}_{\text{APPROVED}} - \sum \text{Расходы}$$

- Учитываются **только верифицированные** взносы (`status: 'APPROVED'`).
- Взносы со статусом `PENDING` отображаются в отдельной метрике «На проверке» и не раздувают фактический баланс.

### 4.2. Алгоритм расчёта статуса жильца (`calculateResidentStatus`)
1. **Начисление**: Базовый период включает месяцы от начала действия системы до текущего месяца (`['2026-07', '2026-08', '2026-09']`).
2. При тарифе **1 500 ₽/мес.** сумма начислений за 3 месяца = **4 500 ₽**.
3. **Оплачено**: Сумма всех подтверждённых взносов жителя по категории `MONTHLY_FEE`.
4. **Сальдо (`balance`)**: `Оплачено - Начислено`.
   - **`balance < 0` (DEBT)**: Фиксируется задолженность. Рассчитывается количество месяцев долга и точный перечень неоплаченных месяцев.
   - **`balance > 0` (ADVANCE)**: Фиксируется аванс (оплата вперед). Рассчитывается количество оплаченных вперед месяцев и дата следующего платежа.
   - **`balance === 0` (OK)**: Задолженности нет, всё оплачено вовремя.

### 4.3. Ролевая модель доступа (RBAC)

| Возможность | Житель (`RESIDENT`) | Член совета (`ADMIN`) | Председатель (`SUPERADMIN`) |
|---|:---:|:---:|:---:|

## 5. Запуск проекта

### Вариант 1: Локальная разработка (рекомендуемый)

В режиме разработки Docker запускает только PostgreSQL. Backend запускается локальным Uvicorn, а frontend — локальным Vite с hot reload.

```bash
docker compose up -d db
```

Доступ к сервисам:
- **База данных PostgreSQL**: `localhost:15432` (`user: postgres`, `password: postgres_password`, `db: fund_db`)

В отдельном терминале из корня проекта запустите backend:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r backend\requirements.txt
python -m alembic -c backend\alembic.ini upgrade head
python backend\seed.py
uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload
```

В третьем терминале запустите frontend:

```bash
npm install
npm run dev
```

Frontend: [http://localhost:3000](http://localhost:3000)  
FastAPI Swagger: [http://localhost:8000/api/v1/docs](http://localhost:8000/api/v1/docs)

Остановка базы данных:

```bash
docker compose down
```

## 6. Руководство разработчику для дальнейших доработок

### 6.1. Синхронизация фронтенда с бэкендом
Frontend загружает данные из FastAPI при старте через `src/shared/api/index.ts` и `fundStore.ts`. Изменения основных сущностей отправляются на backend, а localStorage используется как fallback, если API недоступен.

### 6.2. Подключение реального эквайринга (СБП / Тинькофф / ЮКасса)
- В компоненте `src/features/make-contribution/ui/MakeContributionModal.vue` предусмотрена точка интеграции для открытия платёжного шлюза.
- После успешной оплаты вебхук от эквайринга вызывает бэкенд `POST /api/v1/contributions/webhook`, автоматически выставляя статус `APPROVED` без ручной модерации.

### 6.3. Интеграция Telegram-бота для уведомлений
Рекомендуется подключить бота для двух сценариев:
1. **Уведомление председателя/совета**: При поступлении нового чека в чат совета приходит сообщение с фото чека и кнопками «Одобрить» / «Отклонить».
2. **Уведомление жителя**: Личное оповещение собственника об одобрении взноса, изменении тарифа или публикации срочного объявления об отключении воды/электричества.

### 6.4. Формирование официальных PDF-отчетов
В `src/shared/utils/finance.ts` реализован экспорт в CSV. Для генерации официальных актов ревизионной комиссии для очного собрания собственников можно подключить библиотеку `pdfmake` (на клиенте) или библиотеку `WeasyPrint` / `reportlab` на бэкенде.
